صباح الخير ☕ الأسبوع اللي راح كان غريب شوي على عالم البرمجة. ثلاث شركات كبيرة، كل وحدة من جهة، قالت نفس الشي تقريباً: الشغل ما عاد إنكم تكتبون الكود، الشغل إنكم تبنون النظام اللي يكتبه.

الزبدة
  • الصناعة تنتقل من «مطور معه مساعد» إلى «فريق يدير مصنع agents».
  • المهارة الجديدة: تصميم الـ loop والـ harness، مو كتابة السطور.
  • اليوم: ملف واحد يجهّز مشروعكم لأي agent، وأداة تحمي مفاتيحكم السرية.
* * *

الحكاية

الإشارة الأولى: ميتا استحوذت على Conductor، أداة تخلي المطور يشغّل عدة coding agents بالتوازي في مساحات عمل منفصلة. واحد على الواجهة، وواحد على الـ API، وواحد يكتب الاختبارات، وواحد يكتب التوثيق.

الإشارة الثانية: GitHub نشرت تفاصيل بنية تخزين Git الجديدة عندها. في اختباراتها الداخلية تحمّلت 5000 agent على مستودع واحد في نفس اللحظة، و7200 push في الثانية. Git انبنى على افتراض إن البشر هم اللي يسوون الـ commits، والافتراض هذا ما عاد صحيح.

الإشارة الثالثة: تقرير Thoughtworks لاتجاهات نوفمبر حط سؤال واحد في المركز: كيف تنقل الـ agents من تجربة مطور واحد إلى شغل منظم عبر عشرات الفرق؟

الإطار اللي يرتب الفكرة

Addy Osmani من Google يقسّم الموضوع لثلاث طبقات، كل وحدة تحتوي اللي قبلها:

Loop
الوحدة الأساسية: agent ياخذ مهمة، ينفذها، يتحقق من النتيجة، ويعيد لين تنجح.مثال: «أصلح هذا الاختبار الفاشل» مع أمر يتأكد إن كل الاختبارات صارت خضراء.
Harness
البيئة المحيطة بالـ loop: السياق، والوصول للنموذج، والتقييم، والـ sandbox، والهوية والصلاحيات، وضبط التكلفة، والمراقبة.هذا اللي يفرق بين agent للتجربة وواحد تقدرون تثقون فيه.
Factory
مجموعة loops مرتبة مثل هيكل تنظيمي: من تحديد وش نبني، للتنفيذ، للتحقق، للنشر، وإشارات الإنتاج ترجع كمهام جديدة.Zach Lloyd مؤسس Warp يقولها مباشرة: هندسة البرمجيات بتصير هندسة مصانع.

وش يتغير فعلياً في شغلكم؟

قبلبعد
تكتبون الكودتصممون النظام اللي يكتبه
تختبرون هذا الـ implementationتتحققون إن أي كود يطلع من العملية صحيح
تقيسون بعدد الـ tokens أو السطورتقيسون التكلفة لكل مهمة مكتملة
عنق الزجاجة: كتابة الكودعنق الزجاجة: المراجعة، والسياق، ووضوح المواصفات

الرأي المعاكس

مو الكل مقتنع. Kent C. Dodds رد على مذكرة Warp وقال إن رؤية «المصنع» صحيحة في جزء منها، لكنها تنسى سياق المنتج، وإن الشغل في النهاية يرجع للمستخدم. وفي InfoWorld طرح Nick Hodges سؤال أصعب: إذا الـ agents صاروا يسوون المهام الصغيرة اللي كان الجونيور يتعلم منها، من وين بيجينا السينيور مستقبلاً؟

الكود صار رخيص. الحكم الهندسي، ووضوح المواصفات، وفهم المستخدم صاروا هم القيمة.

طبّقوها اليوم

جهزوا مشروع واحد من مشاريعكم عشان أي agent يقدر يشتغل فيه بدون ما يسألكم. الـ agent يحتاج أمر واحد يشغّل المشروع كامل بنفس الطريقة كل مرة.

  1. أنشئوا ملف AGENTS.md في جذر المستودع.
  2. اكتبوا فيه ثلاثة أشياء بس: كيف يشتغل المشروع، وكيف تشتغل الاختبارات، ومتى تعتبر المهمة منتهية.
  3. اعطوا أي coding agent مهمة صغيرة، وشوفوا هل خلّصها بدون أسئلة.
# AGENTS.md
## Run
make dev            # starts API + web + db (docker compose)
## Verify
make test && make lint
## Definition of done
- All tests green, no new lint warnings
- New behavior has a test
- No secrets in diff

على السريع

أمن

5 دقائق بس. رصدت Microsoft مهاجمين يستخدمون أدوات agentic AI للبحث عن مفاتيح سرية مكشوفة في مستودعات GitHub العامة. في حادثة وحدة انتقل الـ agent من اكتشاف المفتاح إلى سحب بيانات من Azure Key Vault في حوالي 5 دقائق. حذف المفتاح من المستودع ما يكفي، لازم تلغونه وتصدرون واحد جديد.

ريادة

أكبر جولة في نوفمبر. منصة fal للبنية التحتية للذكاء الاصطناعي التوليدي جمعت 1.6 مليار دولار (Series E و F) في 3 نوفمبر، يعني تقريباً نصف 3.3 مليار جمعتها شركات الذكاء الاصطناعي في أول أيام الشهر.

Java

بعد سبع جولات تجريبية. ميزة Structured Concurrency (JEP 543) صارت نهائية في JDK 28. المهام المتفرعة تعيش وتنتهي مع المهمة الأم، فتقل التسريبات والأخطاء في الكود المتزامن.

صحة

تمرين على معدة فاضية؟ تحليل لـ 28 تجربة على بالغين أصحاء لقى إن التمرين وأنت صايم يرفع السكر والإنسولين بعد التمرين ويقلل الأحماض الدهنية الحرة، مقارنة بالتمرين بعد الأكل.

أداة اليوم: Gitleaks

أداة مفتوحة المصدر تفحص الكود وتاريخ Git كامل بحثاً عن مفاتيح وكلمات مرور مكشوفة. ركّبوها كـ pre-commit hook عشان توقف أي commit فيه سر قبل ما يطلع. ومع خبر Microsoft فوق، صارت ضرورية.

brew install gitleaks
gitleaks git -v                     # scan full history
gitleaks git --pre-commit --staged  # before each commit
